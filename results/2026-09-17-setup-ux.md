이번 실행은 제품 설정 초안의 작성·재개·출력과 기존 패키지/설정 회귀다. 실제 NIGO JAR/JRE·고객 키·DB를 사용하지 않았으며 installer·init/start/stop·launchd 또는 G1-M 인수가 아니다.

## 자동 검증

| 실행 | 결과 |

초기 테스트에서는 sandbox가 test-owned Unix socket 생성 자체를 거부했다. 특수 파일 거부 테스트를 생략하지 않고 해당 임시 파일 생성을 허용한 실행에서 전체 83개를 다시 검증했다. 외부 네트워크 listener나 NIGO 노드는 실행하지 않았다.

주요 회귀 조건:

- 유효한 항목만 checkpoint에 저장하고 잘못된 값·unknown/duplicate 필드는 거부한다. 입력 원문을 오류 결과에 되풀이하지 않는다.
- `:back`, 취소·EOF, 불완전 초안 재개, 입력 오류 수정, 대화형 저장 확인과 비대화형 JSON 하나 출력을 확인했다.
- import의 상대 참조는 원본 config 기준으로 절대화한다. 이후 cwd·원본 파일 변경이 저장된 참조를 바꾸지 않는다.
- 0700 workspace·0600 checkpoint/출력, 원자적 신규 publish, 동시 저장 충돌, incomplete private 파일과 손상된 published 파일의 구분을 검증했다.
- 기존 파일·symlink·외부 hardlink·잘못된 권한/종류, 교체된 workspace inode, 오래된 세션의 export를 거부한다.
- 누락된 체인/키 참조 아래를 workspace로 지정해도 자료 경로를 디렉터리로 만들지 않는다. 데이터·초안 기록·참조 자료와 출력의 겹침을 거부한다.
- Mac의 실제 대소문자 alias와 미생성 Unicode 정규화/case alias를 검사한다. case-sensitive Mac에서도 보수적인 거부가 가능하다.
- 출력 성공 후 실제 설정 파일 metadata와 SHA를 보고한다. 로컬 검사에 통과해도 엔진 검사는 `NOT_CHECKED`, 전체 사전 검사는 `INCOMPLETE`다.

## 실제 Mac CLI·터미널 확인

release CLI를 PTY에서 실행하여 인스턴스 이름과 공개 node ID를 입력한 뒤 Ctrl-C로 중단했다. 같은 workspace의 `--resume`은 세 번째 데이터 위치 질문에서 재개했고 `:cancel`은 exit 5로 저장한 두 항목을 보존했다. Ctrl-C 자체의 exit 값은 터미널/프로세스 종료 결과이며 구조화 CLI 취소 계약으로 해석하지 않는다.

예시 제품 config를 가져온 별도 PTY에서는 누락된 자료의 한국어 수정 안내를 확인했다. `export`에서 `n`을 선택했을 때 파일이 생성되지 않았고, 다시 `export`/`y`를 선택했을 때 새 `instance.json`을 0600으로 저장하며 exit 0을 반환했다. 결과 화면은 저장 개수·작업/출력 위치·수정/미검사 개수를 표시하고 엔진 준비 완료를 주장하지 않았다.

| 실제 JSON CLI 확인 | exit / reason |
| --- | --- |
| version | 0 / VERSION, `setup.draft` capability |
| 미완성 초안 비대화형 재개 | 5 / SETUP_DRAFT_INCOMPLETE |
| 완성 초안 비대화형 재개 | 0 / SETUP_DRAFT_SAVED |
| 내보낸 설정의 config validate | 0 / PRODUCT_CONFIG_VALIDATED |
| init | 4 / CAPABILITY_NOT_IMPLEMENTED |

시험 후 예시 경로의 data·secret 디렉터리가 생성되지 않았음을 확인했다. 예시 파일의 참조는 미제공 상태를 유지한다.
