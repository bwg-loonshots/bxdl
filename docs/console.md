# 콘솔 홈과 내 목록

**추가 개발 중단:** 사용자 확인 결과 직관성이 부족하여 2026-10-22부터 직접 CLI 개선을 우선한다. 이 문서는 보존한 기존 console의 실제 기능 설명이며 새 화면·설치·운용 연결의 작업 계획이 아니다. 최신 계획은 [CLI 우선 설계](../design/2026-10-22-cli-simplification.md)를 따른다.

`bxdl console`은 터미널에서 기존 노드·설치 세션을 찾고 저장 기록을 확인하는 진입점이다. 웹서버를 실행하지 않는다. 현재 UX-03은 홈·목록·명시 경로 연결과 [이름 기반 설치 자료 준비·재개](./preparation.md)를 제공한다. 실제 설치·운용의 후속 개선은 직접 CLI로 진행한다. 기존 개별 CLI는 그대로 사용한다.

## 시작

```sh
bxdl console
bxdl console --home /absolute/new-console-home
bxdl console --instance /absolute/existing-control
bxdl console --home /absolute/console-home --instance /absolute/existing-control
bxdl console --help
```

Mac 기본 관리 위치는 `$HOME/Library/Application Support/BXDL`이다. 다른 OS에서 개발용 탐색을 실행하려면 `--home`을 명시한다. 기존 설치의 OS 지원 범위를 확대하는 기능은 아니다. 경로 입력에는 공백·한글을 사용할 수 있지만 심볼릭 링크와 `~` 축약은 받지 않는다. 쉘에서는 `"$HOME/..."`처럼 확장된 절대경로를 전달할 수 있다.

홈과 목록을 여는 것만으로 폴더를 만들지 않는다. **새 관리 위치는 목록 저장 또는 새 준비 세션 생성을 승인할 때 준비한다.** 기존 BXDL 관리 marker가 없는 폴더는 자동 채택하거나 권한을 바꾸지 않는다. 과거 기본 `setup`으로 만든 `BXDL/setup`만 있는 경우에도 그 상위 폴더를 자동 전환하지 않는다. 이때 새 `--home`을 지정하고 기존 세션을 명시 연결한다.

stdin·stdout·stderr가 모두 터미널이어야 한다. `--json`, 파이프 입력, 출력 리다이렉션은 console 본문을 시작하기 전에 거절한다. 자동화는 기존 JSON 명령을 사용한다. 순수 도움말은 비TTY에서도 조회할 수 있다.

## 메뉴

| 홈 번호 | 현재 동작 |
| --- | --- |
| 1 | 새 설치 준비·이름 기반 재개. `setup new/resume`과 동일한 문답 |
| 2 | 목록에 저장한 설치·제품 초안·네트워크 준비 세션 |
| 3 | 목록에 저장한 등록 노드 |
| 4 | 종류와 기존 폴더 경로를 직접 지정해 읽기 |
| 5 | 명시 관리 위치와 사용 범위 안내 |
| 0 또는 Enter | 콘솔 종료 |

기존 경로 열기에서 등록 노드의 **control**, `setup --install`의 **workspace**, 제품 초안 **workspace**, `setup --network`의 **workspace**, 이름 있는 설치 준비 **session** 중 하나를 고른다. data 폴더나 키 파일을 입력하지 않는다. 전체 디스크 검색, 재등록, 기존 DB 채택, V1/V2 변환은 수행하지 않는다.

대상 화면에서는 다음을 제공한다.

1. **등록·세션 저장 기록 다시 읽기:** 같은 폴더 identity·지원 schema를 재검사한다. 현재 서비스 조회는 아니다.
2. **내 목록에 저장 / 목록의 기록 갱신:** 별칭과 공개 저장 단계를 `y` 또는 `yes`로 승인해 기록한다. 같은 이름의 서로 다른 대상은 고유 목록 ID로 구분한다.
3. **상세 위치·기존 명령:** 기본 목록에서 숨긴 대상 경로와 기존 명령을 명시적으로 표시한다. 자동 실행하지 않는다.
4. **목록에서 숨기기:** 이미 저장한 항목만 별도 승인 후 목록에서 뺀다. 노드 중지·설치 제거·세션/DB 삭제와 다르다.

`:help`는 현재 입력의 도움말, `:back`은 이전 화면, `:cancel` 또는 EOF는 중단이다. 승인 질문에서 Enter·`:back`은 변경하지 않는다. 취소 전에 이미 승인한 목록 변경은 보존한다. 콘솔 종료는 노드 중지 요청이 아니다.

## 기록과 현재 상태

목록은 **저장한 관측 시각과 공개 단계**만 보여준다. 목록을 여는 동안 각 노드를 자동 조회하지 않는다. 항목을 고르면 그 대상의 기존 기록을 검증해 읽으며 저장된 초기화 완료를 runtime READY로 바꾸지 않는다. 현재 서비스·합의·정족수는 항상 별도 미조회/미확인으로 둔다.

등록 V1/V2의 조회에서는 현재 CLI와 설치된 `bin/bxdl`의 정확한 파일 내용 일치 여부를 표시한다. 같은 버전 문자열만 비교하지 않는다. `일치`는 서명·전체 package·운용 입력 검증이나 시작 승인 완료가 아니다. 새 CLI를 기존 archive에 덮어쓰지 않는다.

설치 세션은 기존 `Workflow::resume`의 짧은 잠금 안에서 저장 요약만 읽고 즉시 닫는다. 다른 설치 도우미가 세션을 쓰고 있으면 사용 중으로 안내한다. reconcile·init·start·상태 API는 호출하지 않는다. 네트워크 세션은 기존 재개 규칙에 따라 참조 제품/network 자료와 pin 검증을 요구할 수 있다.

## 관리 자료와 실패 처리

새 관리 root는 0700, marker·lock·카탈로그 checkpoint는 0600이다. 탐색 목록에는 고유 ID·별칭·대상 종류/정규 경로·root device/inode·schema·공개 단계·기록 시각을 보관한다. 자격 자료 내용·경로·pin·원문 엔진 reason은 카탈로그 DTO에 넣지 않는다. 대상의 비공개 저장 기록 자체를 읽는 기존 검증 정책은 유지한다.

카탈로그는 최대 256항목, checkpoint당 256KiB, 최대 4096 revision이다. 목록 변경 시 짧은 잠금과 저장본 대조로 동시 덮어쓰기를 막으며, 사용자 입력을 기다리는 동안 잠금을 잡지 않는다. 홈·marker·lock·catalog와 대상의 소유권/권한·symlink·identity를 검사한다. 홈 1번은 승인 후 `sessions/<이름>`에 새 준비 기록을 만든다. 홈 2번은 명시 저장한 카탈로그 목록이며 준비 세션을 자동 추가하지 않는다. 준비 세션의 이름 목록은 홈 1번 → 재개에서 볼 수 있다. `instances/<항목>`의 실제 등록은 후속이다.

대상 누락·교체·지원되지 않는 schema는 자동 재연결하지 않는다. 손상되거나 한도에 도달한 목록도 초기화하지 않는다. 명시 경로 열기와 기존 CLI는 계속 사용할 수 있으며, 목록 저장 실패를 설치·등록 실패로 바꿔 재실행하지 않는다. 저장 성공 확인이 불가능한 경우에는 홈에서 목록을 다시 확인한다. 관리 위치의 새 쓰기가 대상의 DB·package·자료 참조를 침범하지 않도록 검사한다.

완료된 설치 session의 생성 제품 JSON은 운용 입력이므로 계속 보존한다. 목록에서 숨기기는 운용 자료 보존 정책을 바꾸지 않는다.

## 개발 빌드로 확인

현재 checkout에서 빌드한 CLI로 실행한다. 이전 RC.3 package에는 이 명령이 없다.

```sh
cargo build --locked
./target/debug/bxdl console --home /absolute/new-console-home
```

새 설치부터 반복 운용까지의 예정 동선을 먼저 볼 때는 [독립 터미널 체험판](../design/prototypes/integrated-operations-ux-demo.md)을 쓴다. 체험판은 메모리 예시이며 실제 console의 현재 구현 범위와 다르다. 새 package 실인수와 처음 사용자 과업은 [UX-07](../design/2026-10-22-integrated-operations-ux-implementation-plan.md#ux-07-새-패키지-인수와-사용자-과업)에서 검증한다.

홈·목록 최초 구현의 검증은 [UX-02 검증 기록](../results/2026-10-22-ux02-console-catalog.md)에 있다. 실제 노드/새 package의 인수와 구분한다.

이름 기반 준비·재개의 현재 검증 범위는 [UX-03 결과](../results/2026-10-22-ux03-preparation.md)를 따른다.
