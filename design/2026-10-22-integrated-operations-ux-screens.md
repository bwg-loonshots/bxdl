# 통합 설치·운용 UX 화면 시안과 동작 명세

- 작성일: 2026-10-22 / 상태: **설계 시안·미구현**.
- 기준 설계: [통합 UX](./2026-10-22-integrated-operations-ux.md), 작업 순서: [구현 계획](./2026-10-22-integrated-operations-ux-implementation-plan.md).
- [클릭 가능한 HTML 시안](./prototypes/integrated-operations-ux.html)은 화면 이동과 예시 상태만 바꾼다. 제품 서버·CLI·파일·네트워크·서비스를 호출하지 않는다. 웹 관리 제품을 새로 제안하는 산출물이 아니라 터미널 화면을 검토하기 위한 모형이다.
- [터미널 체험판](./prototypes/integrated-operations-ux-demo.md)은 실제 번호·입력·개별 승인 동선을 메모리 상태로 체험한다. 종료 시 상태가 사라지며 제품 CLI에 연결하지 않는다.
- 모든 이름·시간·경로·관측은 예시다. 시안의 “완료/확인”은 실제 인수 결과가 아니다.

## 1. 공통 조작과 표시

실제 구현은 번호 선택·일반 텍스트 입력으로 동작하는 터미널 도우미를 우선한다. 화면 지우기·색상·마우스·화살표 키가 없어도 진행할 수 있어야 한다. 긴 화면은 요약을 먼저 보여주고 상세를 선택한다. HTML의 마우스 버튼은 해당 선택지를 표현한다.

| 입력 | 공통 의미 |
| --- | --- |
| 번호 또는 표시한 명령 | 해당 선택. 변경 작업은 별도 확인 화면으로 이동 |
| Enter | 명시된 읽기/돌아가기/저장 기본 선택만. 승인 화면에서는 실행하지 않음 |
| `:help` | 현재 항목의 의미·자료 담당·예시·조작 안내. 파일 경로로 저장하지 않음 |
| `:back` | 이전 편집/화면. 이미 실행한 작업을 되돌리지 않음 |
| `:cancel` / EOF | 저장된 진행을 보존하고 종료. 이미 실행된 노드를 중지하지 않음 |
| `y` / `yes` | 현재 확인 화면의 한 작업만 승인. 다음 init/start 승인을 포함하지 않음 |

`:help`/`:back`/`:cancel`은 예약 입력이다. 같은 이름의 파일은 `./:help` 또는 절대경로로 명시하도록 안내한다. 메타 명령을 문자 경로로 오해하지 않는다. 비TTY 경로는 기존 명령·JSON으로 안내하며 문답 입력을 소비하지 않는다.

원문 비밀번호·private key·원문 로그는 표시하지 않는다. 공개 값·주소·포트·노드 이름은 검토 가능하게 보여준다. 자료 경로가 필요한 로컬 상세 화면에서는 사용자가 선택한 자료만 안전하게 표시하며 지원 보고서에는 경로/credential을 그대로 복사하지 않는다.

## S01. 홈

```text
BXDL  ·  Mac 사용자 노드

1  새 노드 설치
2  중단한 설치 이어하기
3  내 노드 관리
4  도움말과 준비물
0  종료

선택 [0] >
```

처음 실행해 목록이 없으면 “아직 등록한 목록이 없습니다. 기존 노드는 경로로 연결할 수 있습니다.”를 표시한다. 표시만으로 관리 폴더를 만들거나 디스크 전체를 검색하지 않는다. 패키지 제작자는 도움말의 별도 제작자 명령으로 이동한다. 운영자 첫 화면에 전체 저수준 명령을 나열하지 않는다.

## S02. 준비자료 확인

```text
새 노드 설치  ·  1/4 준비자료

제품 package + engine lock     선택됨 · 검증 필요
독립 경로에서 확인한 신뢰키    선택 필요     [공급 담당자]
승인된 체인·공개 노드 목록     선택됨 · 검사 필요
이 노드의 키·인증서 자료       일부 미제공   [네트워크 관리자]

1  제품 공급 자료 선택
2  승인된 네트워크 자료 선택
3  내 노드의 자격 자료 선택
4  준비자료 검사
5  필요한 자료와 요청 담당 보기
0  초안 저장 후 나가기

아직 설치·DB 초기화·노드 시작을 하지 않았습니다.
```

자료 선택은 기존 파일 경로이며 첫 버전에는 새 bundle 형식이 없다. 미제공과 잘못된 자료를 구분한다. 신뢰키를 archive 옆에서 자동 채택하지 않는다. 서명 없는 fixture는 고급 개발 선택으로 분리한다. native가 이미 있으면 “기존 제품/native 사용”을 선택하고, 없으면 S03의 기존 network 계약으로 준비한다.

기본 관리 루트가 없을 때는 사용할 위치와 새로 만들 부모를 먼저 표시한다. “이 위치에 설치 준비 기록과 폴더를 만들까요? [y/N]”를 확인하고 최소 폴더만 준비한다. package/control/data 자체 생성은 기존 설치·등록/init 단계에서 맡는다.

## S03. 내 노드 설정·수정

```text
새 노드 설치  ·  2/4 내 노드 설정

1  표시 이름           validator-a
2  승인 목록의 내 노드  validator-a  ·  공개 ID 확인됨
3  노드 HTTP           127.0.0.1:18080
4  P2P 연결 주소       192.0.2.10:19090  [예시 주소]
5  네트워크 참여       기존 네트워크 참여
6  저장 위치           BXDL 기본 관리 위치
7  자격 자료           Validator / TLS / 신뢰 저장소 · 확인 필요
8  고급 설정           TLS 형식·archive·기동 후 합의 정책

수정할 번호 / review 검토 / :back / :cancel >
```

공개 network 자료 경로에서는 ID·peer/pin을 승인 목록과 대조하고 자기 노드를 선택한다. 목록에서 선택할 수 없으면 임의 ID로 진행하지 않고 S02로 안내한다. 이미 준비된 제품/native 경로에서는 그 둘의 identity·chain 일치로 대상을 확인하며 network JSON을 추가로 강제하지 않는다. 세부 값은 상세에서 확인하고 표시 이름과 engine identity는 구분한다. 권한·chain 정책·기동 후 합의 시작은 별도 설명하며 단순 기본값으로 추정하지 않는다.

항목 하나를 수정하면 해당 항목만 다시 묻고 검토표로 돌아온다. 수정 전후의 공개 값과 무효화되는 계획을 보여준다. 승인 자료 변경이 필요한 경우 “자료를 새로 받아 새 revision을 준비”하도록 안내한다. native를 자동 보정하거나 기존 생성 파일을 덮어쓰지 않는다.

## S04. 설치 계획과 확인

```text
새 노드 설치  ·  3/4 계획 검토

대상 노드         validator-a / 승인된 체인
선택 제품         BXDL 후보 / NIGO RC.3 / 선정 runtime
생성할 자료       새 package·설정·인스턴스 등록
데이터            새 경로 · 아직 초기화하지 않음
주소·네트워크     공개 설정 요약 / peer 수 / 참여 방식
체인 정책         자산 등록 모드·자격 목록·genesis 고정 안내
보존할 자료       설치 기록·설정·chain·키 참조
공간 안내         package + trust archive + 시도별 snapshot 필요

1  설치·등록하기
2  항목 수정
3  경로·버전·검사 상세
0  저장 후 나가기
```

설치를 선택하면 별도 확인문을 표시한다.

```text
표시한 새 경로에 설정과 패키지를 설치하고 등록할까요?
DB 초기화와 노드 시작은 이후 별도로 확인합니다. [y/N] >
```

정확히 산정 가능한 공간과 추가 운용 공간을 구분한다. 계산하지 못한 전체 용량을 충분하다고 표시하지 않는다. 입력 bytes나 대상이 변경되면 이 승인은 무효이며 새 계획을 확인한다.

## S05. 실행 단계와 설치 완료

```text
새 노드 설치  ·  4/4 실행

패키지 설치       완료 [예시]
인스턴스 등록     완료 [예시]
데이터 초기화     아직 실행하지 않음
노드 시작         아직 실행하지 않음

다음: 새 데이터 초기화
1  초기화 내용 확인
2  등록한 노드 보기
0  여기까지 저장하고 종료
```

초기화 확인에는 새 DB·체인·genesis 고정 정책을 표시하고 별도 `[y/N]`을 받는다. 성공 뒤 “지금 시작”은 다시 별도 확인이다. 어느 단계에서 나가도 남은 작업을 예약하지 않는다.

```text
validator-a를 지금 시작할까요?
Mac 사용자 로그인 세션에서 실행합니다.
터미널을 닫아도 계속 실행될 수 있고, 로그아웃하면 종료됩니다.
다음 로그인에서 자동으로 시작하지 않습니다. [y/N] >
```

진행 중에는 실제 관측 가능한 작업·진입 단계·경과 시간만 표시한다. `startupStage`를 전체 진행률로 환산하거나 완료한 검사로 단정하지 않는다. 시작 요청 뒤 같은 시도의 로컬 READY를 관측하면 S08로 연결한다. 관측 시간이 끝나면 S10이며 자동 start 재시도는 없다.

완료 화면에는 “설치 기록에는 운용 설정이 포함되어 계속 필요합니다”와 `bxdl console`로 다시 노드를 찾는 방법을 표시한다. 새 통합 CLI는 이를 포함한 새 package에서 검증해야 한다.

## S06. 중단한 작업 이어하기

```text
설치 이어하기

1  validator-a  ·  설치·등록까지 기록됨  ·  재검증 전
2  validator-b  ·  자격 자료 입력 중     ·  재검증 전
3  기존 작업 폴더를 경로로 열기
0  홈

선택한 작업의 입력과 실제 결과를 확인한 뒤 다음 단계를 안내합니다.
```

목록의 checkpoint는 완료 증명이 아니다. 선택 후 기존 소유·입력 검사를 수행하며 확인된 결과만 현재 화면에 올린다. 기존 세션을 새 포맷으로 옮기지 않는다. 지원되지 않는 형식은 기존 CLI와 해당 문서로 안내한다.

의도 기록 뒤 작업 결과가 불명확하면 S10으로 간다. 설치/등록의 완료를 재구성할 소유 증거가 없으면 새 설치나 덮어쓰기를 제안하지 않는다. `resume-init`은 기존 API의 적용 조건을 검사하는 별도 명시 작업으로만 제공한다. 실행 이력이 있는 설치를 열어도 start를 자동 반복하지 않는다.

## S07. 내 노드 목록

```text
내 노드

1  validator-a  ·  마지막 기록: 실행 중 / 13:40  ·  현재 미조회
2  validator-b  ·  마지막 기록: 정상 종료 / 12:10 ·  현재 미조회
3  기존 인스턴스 경로 연결
0  홈

같은 이름이 있으면 목록 식별자와 위치 상세로 구분합니다.
```

목록은 카탈로그의 저장 관측이다. 노드 선택 후 “새로 확인”으로 현재 상태를 조회한다. 경로 없음·inode 변경·다른 UID·손상은 경고 항목으로 남기고 임의 재등록하지 않는다. “목록에서 숨기기”는 실행 노드/DB/등록을 제거하지 않는다고 별도로 설명한다.

## S08. 노드 운용

```text
validator-a  ·  노드 관리

상태              실행 중 · 로컬 준비 완료 [관측 예시]
마지막 확인       13:40:02 · 선택한 실행 시도
네트워크 합의     미확인
운용 방식         Mac 사용자 세션 · 로그아웃 시 종료

1  상태 새로 확인
2  노드 중지
3  최근 기록 보기
4  지원 보고서 저장
5  상세 정보와 사용 가능한 명령
0  내 노드 목록
```

초기화 전에는 초기화 확인, 시작 전/정상 종료 확인 뒤에는 시작 확인, STARTING에는 같은 시도 대기를 제시한다. 불명 상태에는 안전한 읽기·지원 행동만 제시한다. UI 선택 직전에 잠금·현재 identity·입력·서비스 상태를 API로 다시 검사한다.

새 console과 설치된 CLI가 다르면 실행 호환성을 확인하지 못한 변경 선택을 비활성화하고 S10의 CLI 안내를 표시한다. 검증된 기존 CLI의 명령을 보여줄 수 있지만 자동 실행하지 않는다. 상세에는 service/engine/readiness·attempt·reason·마지막 진입 단계 등 기존 근거를 둔다.

## S09. 중지와 같은 DB 재시작

```text
validator-a 중지

현재 선택한 실행 시도에 정상 종료를 요청합니다.
데이터·키·설치본·기록은 보존합니다.
종료 확인 전에는 다시 시작하지 않습니다.

정상 종료를 요청할까요? [y/N] >
```

```text
validator-a  ·  정상 종료 확인됨 [예시]

1  같은 데이터로 다시 시작하기 → 별도 시작 확인
2  기록 보기
0  노드 관리로 돌아가기
```

정상 stop report·프로세스 부재·잠금·등록 정리가 필요한 기존 조건을 따른다. 프로세스가 없거나 job이 안 보인다는 이유만으로 정상 종료 완료로 표시하지 않는다. 중지 관측 시간 만료와 GUI 부재는 S10이다. 중지 뒤 취소/EOF는 노드를 정지 상태로 남기며 다음 start를 예약하지 않는다. 설치 journal을 리셋하지 않는다.

승인한 control identity/attempt와 실제 조작 대상을 결속한다. 확인창을 띄운 뒤 다른 CLI가 새 시도로 바꾸면 이전 승인으로 새 시도를 중지하지 않고 “대상이 변경됐습니다. 상태를 다시 확인하세요”로 돌아간다.

## S10. 오류·대기·지원 분기

| 사례 | 핵심 문구 | 권장 선택 | 제공하지 않는 동작 |
| --- | --- | --- | --- |
| 설치 전 비밀번호 파일 누락 | “Validator 비밀번호 파일을 읽을 수 없습니다. 설치는 시작하지 않았습니다.” | 해당 자료 다시 선택 → 재검사 | 원문 비밀번호 입력 |
| 시작 관측 시간 만료 | “관측 시간이 끝났습니다. 노드는 계속 시작 중일 수 있습니다.” | 같은 시도 다시 확인 | 자동 start/실패 확정 |
| STOPPED이나 종료 확정 필요 | “정지가 관측됐지만 재시작 전 종료 확인이 필요합니다.” | 명시 중지로 종료 확인 | 바로 새 start |
| GUI 세션 확인 불가 | “이 Mac 로그인 세션의 서비스를 확인할 수 없습니다.” | 세션 범위 설명·기록 보기 | 자동 daemon 전환 |
| 이전 실행 결과 불명/gate 거부 | “안전하게 다시 시작할 조건을 확인하지 못했습니다.” | 정제 보고서 만들기·지원 안내 | 잠금 삭제·UNKNOWN 해제·재초기화 |
| CLI 바이트 불일치 | “선택한 설치와 이 CLI가 다릅니다.” | 검증한 설치 CLI/현재 지원 범위 보기 | 자동 exec·CLI 덮어쓰기·upgrade |
| 목록 저장 실패 | “등록은 완료됐지만 목록에 저장하지 못했습니다.” | 실제 등록 경로로 열기·목록 저장 재시도 | 등록·init 반복 |

일반 형식 오류에 작업 결과 불명 경고를 붙이지 않는다. “어디까지 완료됐는가”와 “그 완료를 무엇으로 확인했는가”를 분리하며, 제공할 수 없는 복구는 명확히 지원 검토 대상으로 표시한다. 보고서 유실처럼 같은 status를 반복해도 해결되지 않는 상태에는 무한 재시도 안내를 하지 않는다.

## S11. 최근 기록과 지원 보고서

```text
validator-a  ·  지원 자료

자료 범위       최신 초기화·서비스 시도의 정제한 저장 기록
현재 상태       이 화면에서는 조회하지 않음
보고서 위치     BXDL 관리 위치 / reports / 새 파일

1  최근 정제 기록 보기
2  새 보고서 만들기
3  현재 상태 확인 화면으로 이동
0  노드 관리
```

출력은 매번 충돌하지 않는 새 이름을 제안하고 기존 파일을 덮어쓰지 않는다. 부모·겹침·권한·등록 검증은 기존 diagnose 정책을 따른다. 실제 저장 확인 뒤 파일 위치와 수집 범위를 표시한다. `partial=true`이면 “파일 저장됨 · 일부 자료 누락”과 사유를 함께 표시한다. 파일 생성 성공은 현재 건강 상태나 초기화의 성공이 아니다.

원문 stdout/stderr·private 자료를 자동 추가하지 않는다. 최초 범위는 현재 최신 시도만이며 과거 시도 탐색·실시간 raw follow는 후속이다. 지원 보고서는 자동 전송하지 않고 사용자가 검토해 전달한다.

## 3. 시안과 제품 구현의 차이

HTML과 터미널 체험판은 선택·확인·뒤로가기·사례 전환을 검토하기 위한 예시 상태 기계다. 실제 파일 선택/검사, 저장 내구성, CLI 일치, launchd, 잠금, 터미널 접근성·좁은 폭, 재개/동시 변경은 시안으로 검증하지 않는다. 실제 TTY 회귀와 새 package 인수, 처음 사용자 과업은 [구현 계획 UX-07](./2026-10-22-integrated-operations-ux-implementation-plan.md#ux-07-새-패키지-인수와-사용자-과업)에서 별도로 수행한다.
